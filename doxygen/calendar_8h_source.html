26/** This method converts 'utcEpochMilliseconds' - UTC time as milliseconds
27 since the Epoch (1970-01-01 00:00:00) - to a broken-down calendar time
28 representation, expressed in Coordinated Universal Time (UTC). The result
29 is stored in the user-provided 'result' struct tm instance. All of the
30 standard struct tm fields are set (tm_isdst is always zero). The
31 sub-second portion [0-999] of 'utcEpochMilliseconds' is returned via
32 'dstMilliseconds'. The conversion can not fail.
33
34 The conversion is done arithmetically using Howard Hinnant's (public domain)
35 date algorithms (http://howardhinnant.github.io/date_algorithms.html),
36 i.e. it does not use the C library's gmtime() and it is thread-safe without
37 requiring a mutex. The results are identical to gmtime() - proleptic
38 Gregorian calendar, no leap seconds - for every 'utcEpochMilliseconds'
39 value, and the conversion is not limited by the size of time_t (e.g. it is
40 valid after 2038 on platforms with a 32-bit time_t).
41
42 NOTE: This method is preferred over gmtimeMT().
43 */
44void msecToCalendar( uint64_t utcEpochMilliseconds, struct tm& result, uint16_t& dstMilliseconds ) noexcept;
45
46/** This method is a guaranteed thread-safe alternative to the C/C++ library's
47 gmtime() call.
48
49 The method converts the calendar time 'timep' to a broken-down time
50 representation, expressed in Coordinated Universal Time (UTC). It may return
51 nullptr when the year does not fit into an integer. The result is stored in
52 the user-provided 'result' struct tm instance.
53
54 NOTE: msecToCalendar() is preferred over this method. msecToCalendar() is
55 thread-safe WITHOUT a mutex, whereas this method's implementation
56 for platforms without gmtime_r()/gmtime_s() (the _ansi variant)
57 serializes calls to gmtime() with a mutex. A mutex is undesirable on
58 platforms that only provide partial priority inheritance (e.g.
59 FreeRTOS).
60
61 NOTE: This method is needed because the KIT library assumes ONLY the C++11
62 language standard. The C++11 standard does NOT guarantee/provide a
63 thread-safe version of gmtime()
64 */
65struct tm* gmtimeMT( const time_t* timep, struct tm* result ) noexcept;
