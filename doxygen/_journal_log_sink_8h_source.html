25/** This concrete class is a 'log sink' that writes the application's log
26 entries to persistent storage using a Journal Record. It extends the
27 Kit::Persistence::Record::Journal::Server with:
28
29 - Pausing updates. When the optional 'pauseUpdates' flag is
30 non-null and set to true, no entries are written to persistent storage.
31 The entries are NOT removed from the log buffer while paused, i.e. no
32 entries are lost (unless the log buffer overflows, see the Logging
33 framework's overflow handling). This allows the application to
34 temporarily reduce/halt write traffic to the storage media.
35
36 The flag is a std::atomic<bool>, i.e. it can be set and cleared from any
37 thread. The sink only reads the flag.
38
39 NOTE: Pausing is timely, NOT immediate. The flag is checked before each
40 entry is removed from the log buffer, i.e. a write that is already
41 in progress (and the entry being written) completes after the
42 flag is set. There is no acknowledgement that the sink has
43 paused
44
45 NOTE: Clearing the flag does not, by itself, trigger writing the queued
46 entries. They are written on the next change notification of the
47 log buffer, i.e. when the next entry is logged. It is recommended
48 that the application logs an entry when it resumes updates.
49
50 - Boot-counter correction. The boot counter (the upper bits of a log
51 entry's timestamp, see Kit::Time::getBootTime()) is zero until the
52 boot-counter record has been loaded from persistent storage. Entries
53 logged before then wait in the RAM log buffer, and would be written with
54 boot counter zero: readers of the journal would see them as entries
55 from a different boot. Also, when the boot-counter record imports the
56 stored (previous boot's) counter and then increments it, an entry logged
57 between the two steps carries the previous boot's counter.
58
59 The RAM log buffer only holds entries from the current boot, so this
60 class captures the current boot counter when the sink is opened, and
61 writes every entry whose boot counter does not match with the current
62 boot counter. The elapsed time is kept.
63
64 IMPORTANT: The application MUST open the sink after the boot-counter
65 record has been loaded (and incremented).
66
67 NOTE: When the RingBufferMP 'incomingEntriesBuffer' is created it MUST be
68 created with the 'initializeMemory' constructor flag set to false,
69 since EntryData_T has a vtable pointer.
70 */

73public:

79 */
