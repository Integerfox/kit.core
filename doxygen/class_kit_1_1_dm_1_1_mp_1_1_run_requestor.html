Detailed Description

This class provides the 'requestor' side of a RunControl Model Point, i.e.

the interface for a client that wants to start, stop, pause, or resume a 'runnable' widget and to monitor the result of the request. The widget's side is the RunManager class.

The class enforces the following policies:

  • Only one request can be in-flight at any given time (the request is ERR_REQUEST_IN_PROGRESS when there is already a request in-flight).
  • A request is NOT_ACCEPTED when the RunControl Model Point is invalid (i.e. the RunManager has not published the widget's state), the widget's state is INVALID or ERRORED, or the request is NOP.

A request that is accepted is PENDING until the RunManager responds. A client monitors the result by attaching an observer and comparing the request's identifier (returned by request()) with the RunControl data's 'requestId' (change notifications may be coalesced, i.e. the client may not see every status transition).

The toJSON() output is that of the RunControl Model Point. The fromJSON() format only supports issuing a request:

val:"START|STOP|PAUSE|RESUME"
Example:
{ name:"mp_runRequestor", val:"START" }

IMPORTANT: This (pseudo) Model Point is transient/run-time state and MUST NEVER be persistently stored.

NOTE: All methods in this class ARE thread Safe unless explicitly documented otherwise.

Reads the status of the most recent request, the identifier of the most recent request (compare with the identifier returned by request() to determine if the status is for the caller's request), and the widget's actual state, i.e.

a convenience for calling read(). The data Model Point's sequence number is optionally returned via 'retSeqNum'. Returns false (and the output arguments are not updated) when the data Model Point is invalid.

This method should NOT be used within an observer's change notification callback (use readStatusAndSync() instead).

RunRequestStatus Kit::Dm::Mp::RunRequestor::request ( RunRequest request,

Makes a request.

Returns PENDING when the request was accepted, and 'retRequestId' is set to the request's identifier. The identifier is used to correlate the request with its result (see readStatus()). Otherwise returns ERR_REQUEST_IN_PROGRESS (a request is already in-flight) or NOT_ACCEPTED (see class description) and 'retRequestId' is not updated. The data Model Point's sequence number (after the operation) is optionally returned via 'retSeqNum'.
