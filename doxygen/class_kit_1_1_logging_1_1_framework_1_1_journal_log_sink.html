Detailed Description

This concrete class is a 'log sink' that writes the application's log entries to persistent storage using a Journal Record.

It extends the Kit::Persistence::Record::Journal::Server with:

  • Pausing updates. When the optional 'pauseUpdates' flag is non-null and set to true, no entries are written to persistent storage. The entries are NOT removed from the log buffer while paused, i.e. no entries are lost (unless the log buffer overflows, see the Logging framework's overflow handling). This allows the application to temporarily reduce/halt write traffic to the storage media.

    The flag is a std::atomic<bool>, i.e. it can be set and cleared from any thread. The sink only reads the flag.

    NOTE: Pausing is timely, NOT immediate. The flag is checked before each entry is removed from the log buffer, i.e. a write that is already in progress (and the entry being written) completes after the flag is set. There is no acknowledgement that the sink has paused

    NOTE: Clearing the flag does not, by itself, trigger writing the queued entries. They are written on the next change notification of the log buffer, i.e. when the next entry is logged. It is recommended that the application logs an entry when it resumes updates.

  • Boot-counter correction. The boot counter (the upper bits of a log entry's timestamp, see Kit::Time::getBootTime()) is zero until the boot-counter record has been loaded from persistent storage. Entries logged before then wait in the RAM log buffer, and would be written with boot counter zero: readers of the journal would see them as entries from a different boot. Also, when the boot-counter record imports the stored (previous boot's) counter and then increments it, an entry logged between the two steps carries the previous boot's counter.

    The RAM log buffer only holds entries from the current boot, so this class captures the current boot counter when the sink is opened, and writes every entry whose boot counter does not match with the current boot counter. The elapsed time is kept.

    IMPORTANT: The application MUST open the sink after the boot-counter record has been loaded (and incremented).

NOTE: When the RingBufferMP 'incomingEntriesBuffer' is created it MUST be created with the 'initializeMemory' constructor flag set to false, since EntryData_T has a vtable pointer.
