25/** This class provides the 'requestor' side of a RunControl Model Point, i.e.
26 the interface for a client that wants to start, stop, pause, or resume a
27 'runnable' widget and to monitor the result of the request. The widget's
28 side is the RunManager class.
29
30 The class enforces the following policies:
31 - Only one request can be in-flight at any given time (the request
32 is ERR_REQUEST_IN_PROGRESS when there is already a request in-flight).
33 - A request is NOT_ACCEPTED when the RunControl Model Point is invalid
34 (i.e. the RunManager has not published the widget's state), the
35 widget's state is INVALID or ERRORED, or the request is NOP.
36
37 A request that is accepted is PENDING until the RunManager responds. A
38 client monitors the result by attaching an observer and comparing the
39 request's identifier (returned by request()) with the RunControl data's
40 'requestId' (change notifications may be coalesced, i.e. the client may not
41 see every status transition).
42
43 The toJSON() output is that of the RunControl Model Point. The fromJSON()
44 format only supports issuing a request:
45 \code
46
47 val:"START|STOP|PAUSE|RESUME"
48
49 Example:
50 { name:"mp_runRequestor", val:"START" }
51
52 \endcode
53
54 IMPORTANT: This (pseudo) Model Point is transient/run-time state and MUST
55 NEVER be persistently stored.
56
57 NOTE: All methods in this class ARE thread Safe unless explicitly
58 documented otherwise.
59 */
60class RunRequestor : public PseudoMpBase<RunControl_T, RunControl>
61{
62public:
63 /// Constructor. The RunControl Model Point must outlive the instance
64 RunRequestor( Kit::Dm::IModelDatabase& myModelBase, const char* symbolicName, RunControl& dataMp );
65
66public:
67 /** Makes a request. Returns PENDING when the request was accepted, and
68 'retRequestId' is set to the request's identifier. The identifier is
69 used to correlate the request with its result (see readStatus()).
70 Otherwise returns ERR_REQUEST_IN_PROGRESS (a request is already
71 in-flight) or NOT_ACCEPTED (see class description) and 'retRequestId'
72 is not updated. The data Model Point's sequence number (after the
73 operation) is optionally returned via 'retSeqNum'.
74 */
75 RunRequestStatus request( RunRequest request, uint16_t& retRequestId, uint16_t* retSeqNum = nullptr ) noexcept;
76
77 /// Convenience method. See request()
78 inline RunRequestStatus start( uint16_t& retRequestId, uint16_t* retSeqNum = nullptr ) noexcept { return request( RunRequest::START, retRequestId, retSeqNum ); }
79
80 /// Convenience method. See request()
81 inline RunRequestStatus stop( uint16_t& retRequestId, uint16_t* retSeqNum = nullptr ) noexcept { return request( RunRequest::STOP, retRequestId, retSeqNum ); }
82
83 /// Convenience method. See request()

85
86 /// Convenience method. See request()

89 /** Reads the status of the most recent request, the identifier of the most

91 determine if the status is for the caller's request), and the widget's
92 actual state, i.e. a convenience for calling read(). The data Model
93 Point's sequence number is optionally returned via 'retSeqNum'. Returns
94 false (and the output arguments are not updated) when the data Model
95 Point is invalid.
96
97 This method should NOT be used within an observer's change notification
98 callback (use readStatusAndSync() instead).
99 */
100 bool readStatus( RunRequestStatus& retStatus,

111 */
